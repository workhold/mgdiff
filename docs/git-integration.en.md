# Use MGDiff with Git

[简体中文](git-integration.md)

The MGDiff desktop executable accepts two entry points. In the examples below, `mgdiff` means the path to the actual executable: building or installing the app does not add it to `PATH` automatically.

```text
mgdiff --diff <left> <right>
mgdiff --merge <base> <local> <remote> <merged>
```

`--diff` loads two files or two directories without modifying either input automatically and selects the corresponding comparison mode. `--merge` opens the text three-way merge view and reads Git's initial `MERGED` file. It writes only to the path given as `merged` when you save. Missing input files are treated as empty files. Paths containing spaces are supported when passed as separate command-line arguments.

After `npm run tauri build` on macOS, the executable inside the app bundle is at `src-tauri/target/release/bundle/macos/MGDiff.app/Contents/MacOS/mgdiff`. The standalone build output is at `src-tauri/target/release/mgdiff`. From the project root, get an absolute path and check the CLI:

```sh
APP_BINARY="$(pwd)/src-tauri/target/release/bundle/macos/MGDiff.app/Contents/MacOS/mgdiff"
"$APP_BINARY" --help
```

`/Applications/MGDiff.app/Contents/MacOS/mgdiff` exists only after you install the app bundle in Applications. The desktop app's **Integrations** panel shows its actual executable path. The local Vite preview (`npm run dev`) looks for a built executable through `/__mgdiff/cli-path`; a static browser preview requires you to enter its absolute path. Both can generate Git configuration commands, but the browser page itself cannot receive CLI arguments. Avoid launchers such as `open -a` in Git's tool configuration because they may return before MGDiff exits, while Git must wait for the process.

## Configure difftool

The following examples assume that MGDiff is installed in `/Applications`. Otherwise, substitute the absolute path stored in `APP_BINARY` above, or copy the commands generated by **Integrations**. The outer single quotes defer expansion of `$LOCAL` and `$REMOTE` until Git invokes the tool; the inner double quotes keep paths containing spaces intact.

```sh
git config --global diff.tool mgdiff
git config --global difftool.mgdiff.cmd '"/Applications/MGDiff.app/Contents/MacOS/mgdiff" --diff "$LOCAL" "$REMOTE"'
git config --global difftool.prompt false
```

```sh
git difftool --tool=mgdiff
git difftool --tool=mgdiff --dir-diff --no-symlinks
```

A custom difftool receives `$LOCAL` and `$REMOTE` from Git. `--dir-diff` copies changes into temporary directories. On non-Windows systems, Git may use symlinks in this mode, so `--no-symlinks` lets MGDiff scan actual files. See the [Git difftool documentation](https://git-scm.com/docs/git-difftool).

## Configure mergetool

```sh
git config --global merge.tool mgdiff
git config --global mergetool.mgdiff.cmd '"/Applications/MGDiff.app/Contents/MacOS/mgdiff" --merge "$BASE" "$LOCAL" "$REMOTE" "$MERGED"'
git config --global mergetool.mgdiff.trustExitCode true
```

```sh
git mergetool --tool=mgdiff
```

Git supplies the common ancestor, current branch, incoming branch, and result path as `$BASE`, `$LOCAL`, `$REMOTE`, and `$MERGED`. `$BASE` may be absent; MGDiff treats missing inputs as empty content. MGDiff returns status 0 only after the merged result is saved to the specified `MERGED` path and the window exits normally. Closing without saving returns a nonzero status. `mergetool.mgdiff.trustExitCode=true` tells Git to use that status to decide whether the merge finished. See the [Git mergetool documentation](https://git-scm.com/docs/git-mergetool).

These CLI entry points can also be used by SVN, Mercurial, or other applications that pass file paths to an external tool and wait for it to exit. Supply arguments in the order shown above.
